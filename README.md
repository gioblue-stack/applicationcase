# Цифровой сервис наблюдения пациентов с тревожными и депрессивными расстройствами

> **Прототип (MVP).** Не предназначен для диагностики и лечения. Все данные демонстрационные.

Сервис помогает лечащему врачу вести пациентов с тревогой и депрессией между очными приёмами:
пациент отмечает самочувствие и приём лекарств, раз в неделю заполняет PHQ-9 и GAD-7, а врач видит динамику
и получает сигналы, когда нужно вмешаться. Главный приоритет — **безопасность при суицидальном риске**
и **достоверность данных**. Требования взяты из «Приложения к Приложению — Полного Положения»; при противоречиях
приоритет у документа. Интерфейс на русском, только для взрослых (18+).

## Что умеет

### Пациент — мобильный сайт (`apps/web-patient`, добавляется на рабочий стол телефона)

- **Вход** по одноразовому коду (телефон или e-mail); первый вход — по коду приглашения врача и с согласием на обработку данных о здоровье.
- **«Сегодня»** — что осталось сделать; маскот-пингвин подсказывает следующий шаг.
- **Дневник** (≈1 мин): настроение, интерес, тревога, контроль беспокойства, сон, силы (0–10), приём лекарств и побочные эффекты. Пропуск хранится как «нет ответа», а не 0.
- **PHQ-9 и GAD-7** раз в неделю: официальный русский текст, результат простым языком и пометка «это не диагноз».
- **Приём лекарств**: «Принял(а) / Пропустил(а) / Изменил(а) дозу / Через 15 минут». При пропуске сразу показывается правило, которое задал врач.
- **Схема лечения** простым языком, включая будущие изменения дозы.
- **План безопасности**: свои сигналы, что помогает, кому позвонить, как сделать обстановку безопаснее.
- **Вопрос врачу** — с предупреждением, что это не канал экстренной связи.
- **Кнопка «Мне сейчас очень плохо»** на каждом экране, в том числе до входа: телефоны помощи (112, телефон доверия, региональные) и красный сигнал врачу.

### Врач — веб-кабинет (`apps/web-doctor`)

- **Вход** по паролю и коду из приложения-аутентификатора (TOTP); автовыход после 30 минут бездействия.
- **Очередь пациентов** по срочности (красные → жёлтые → зелёные) с причинами сигналов.
- **Карточка пациента**: флаги с кнопкой «Взять в работу», графики дневника (пропуски — разрывами, отметки смены лечения), PHQ-9/GAD-7 по неделям с ответами, история уточняющих блоков, приверженность, журнал побочных эффектов, план безопасности.
- **Назначение препаратов**: препарат из демо-базы, доза, время, правило при пропуске, титрация; изменение дозы и отмена. Пациент видит назначение сразу.
- Каждый просмотр данных пациента записывается в журнал доступа.

### Безопасность (суицидальный риск)

Уточняющий блок вопросов открывается автоматически: 9-й вопрос PHQ-9 не «ни разу», резкое падение или стойко низкое
настроение, начало лечения или смена дозы, пропуски и самостоятельная смена дозы, бессонница с сильной тревогой,
тревожный симптом. Уровень (жёлтый / красный / экстренный) определяет сервер; «Не сейчас» и закрытие на середине
тоже дают сигнал врачу (частичный ответ — не ниже красного). Кризисные слова в дневнике и сообщениях сразу
открывают экран помощи. Уведомления врачу нейтральные — без имени пациента и диагноза.

## Структура

| Путь | Что |
|---|---|
| `backend/` | API на FastAPI + PostgreSQL, фоновый воркер, миграции Alembic, тесты. Подробно — [backend/README.md](backend/README.md) |
| `backend/app/domain/` | Клинические правила без БД: протокол риска, подсчёт шкал, флаги, расписания |
| `backend/app/services/` | Оркестрация: оценка + флаг + уведомление врачу + журнал доступа в одной транзакции |
| `apps/web-patient/` | Сайт пациента (Next.js, PWA). Подробно — [apps/web-patient/README.md](apps/web-patient/README.md) |
| `apps/web-doctor/` | Кабинет врача (Next.js) |
| `content/` | Клинический контент в JSON: опросники, тексты, телефоны помощи, кризисные слова, демо-база препаратов и взаимодействий, общие тест-векторы |
| `docs/ARCHITECTURE.md` | Архитектура, сущности, сценарии и принятые решения (В1–В9) |
| `scripts/dev-api.sh` | Локальный запуск: PostgreSQL, миграции, демо-данные, API и воркер одной командой |

**Стек:** Python 3.12+, FastAPI, SQLAlchemy 2, PostgreSQL 16, Alembic · Next.js 15, React 19, Tailwind CSS 4, Recharts · pytest, Vitest.

## Как запустить локально

Нужно: **Python 3.12+**, **PostgreSQL 16** (`brew install postgresql@16`), **Node.js 20+**.
Скрипт ищет PostgreSQL в `/opt/homebrew/opt/postgresql@16/bin`; другой путь задаётся переменной `MC_PG_BIN`.

```bash
python3 -m venv .venv
.venv/bin/pip install -e "backend[dev]"
npm --prefix apps/web-patient ci
npm --prefix apps/web-doctor ci
```

Дальше — три вкладки терминала; каждая команда работает, пока её не остановить (Ctrl+C):

```bash
./scripts/dev-api.sh                       # API на :8000 + воркер; при первом запуске — база и демо-данные
npm --prefix apps/web-patient run dev      # сайт пациента: http://localhost:3001
npm --prefix apps/web-doctor run dev       # кабинет врача: http://localhost:3000
```

При первом запуске `dev-api.sh` создаёт папку `var/` (в git не попадает): локальная база, случайные секреты
разработки в `var/dev-secrets.env` и коды входа в `var/dev-login-codes.txt`. Документация API — http://localhost:8000/docs.

## Демо-доступ

**Пациенты.** На сайте пациента введите телефон и нажмите «Получить код». SMS не отправляются: код — последняя строка
файла `var/dev-login-codes.txt`.

| Пациент | Телефон | Что показывает |
|---|---|---|
| Анна | `+79000000001` | «Зелёный»: стабильное наблюдение на сертралине |
| Игорь | `+79000000002` | «Жёлтый»: три пропуска приёма подряд, рост GAD-7 на 5 баллов, трамадол от другого врача (проверка взаимодействий) |
| Мария | `+79000000003` | «Красный»: 9-й вопрос PHQ-9 не «ни разу» → уточняющий блок → красный уровень |
| Олег | `+79000000004` | Пользователь без врача: экран помощи без упоминания врача |

**Врач.** E-mail `doctor@demo.mindcare.test`, пароль — значение `MC_DEMO_DOCTOR_PASSWORD` в `var/dev-secrets.env`
(генерируется при первом запуске). При первом входе кабинет покажет QR-код для приложения-аутентификатора
(Google Authenticator и подобные).

## Тесты

```bash
cd backend && ../.venv/bin/python -m pytest      # 522 теста; сами поднимают временный PostgreSQL
npm --prefix apps/web-patient test
npm --prefix apps/web-doctor test
```

Тесты бэкенда покрывают клинические правила (уровни риска, подсчёт шкал, флаги, расписания), целостность данных
(отправленные ответы неизменяемы — защищено триггером БД; повторное заполнение — новая версия; идемпотентность
по `client_id`), вход и сессии, доступ врача только к своим пациентам и сквозные сценарии через HTTP.
Тексты опросников сверяются с эталоном по хешу.

## Ограничения прототипа

- SMS, e-mail и push не отправляются: коды входа и уведомления пишутся в лог и в `var/`. Провайдеры подключаются к пилоту.
- Экран помощи без интернета (service worker) работает только по https; в локальной разработке он отключён.
- Есть в API, но пока без экрана: создание пациента с кодом приглашения, ответы на сообщения и факторы риска
  в кабинете врача; ассистент по вопросам о лечении и самопроверка пользователя без врача на сайте пациента.
- Тексты для пациентов помечены как проекты (`approval.status: draft`) и требуют утверждения врачами команды;
  демо-база препаратов и взаимодействий не сверена с инструкциями.
